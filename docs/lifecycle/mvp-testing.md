# Pre-production MVP testing · P0

Validate the MVP candidate with representative people once the core flow is usable
and before any production authorization. This is the lifecycle's single human
validation gate; earlier brief, research, structure, visual-system and prototype
work uses founder decisions, desk evidence, agent review and automated checks.

## Test plan

- [ ] Name the target user, eligibility rule and the task they recently needed.
  Proof: the issue states who qualifies and what successful completion means.
- [ ] Choose a small sample and a predeclared success threshold.
  Proof: the count, denominator, deadline and stop rule are recorded before contact.
- [ ] Run the MVP candidate through the core path and its recovery path.
  Proof: anonymized notes record completion, confusion, failure and recovery.
- [ ] Obtain consent, minimize data, and keep identities in an approved private
  location. Do not make public promises or pay incentives without authorization.
  Proof: the handling plan and redacted evidence link are recorded.
- [ ] Compare the result with the threshold and accessibility/safety constraints.
  Proof: counts, denominators, severity and unresolved risks are visible.

## Founder decision before production

- [ ] The founder records proceed, revise, or stop, with the evidence and scope cuts.
  Proof: the decision links this test and any follow-up issues.
- [ ] Carry failed tasks or unresolved assumptions into release acceptance criteria.
  Proof: each item has an owner, measure and re-test date.

If the product has no meaningful human interaction, record an applicability
exception and equivalent proof such as an expert review, deterministic scenario or
operational rehearsal. An unanswered request is not approval.

design-sprint is an optional method for organizing this gate; it does not require
human participants during earlier design phases.
